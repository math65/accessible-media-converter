- **Fix: extracting the sound of a video could be wrongly reported as a failure.** Some videos carry an audio track shorter than the picture — typically an audio-description track that stops partway through the film. Extracting it (to MP3, for example) produced a correct file containing all of the available sound, yet the application declared "The converted file is unexpectedly short — the conversion likely failed." The end-of-conversion check now compares each output against the source track it actually came from, so these conversions complete normally. The same false alarm also hit video conversions keeping a short audio track alongside a complete one. It is fixed there too.
- **Fix: removing or replacing the cover of a video could delete its picture.** When editing metadata with "Re-tag the original file now", removing or replacing the cover art of a video file also removed the video track itself, and the original was replaced by a file without any picture. Only the cover art is removed now.
- **Fix: a merge could overwrite one of its own source files.** Choosing one of the files being merged as the output destroyed that file while it was still being read, without any error. This choice is now refused with a clear message.
- **Fix: status mix-up in batches containing a cue sheet.** An album split into several tracks shifted the status of every file listed after it, so progress and errors could appear on the wrong row. Each file now shows its own status, and an album reads "Track N of M: …".
- **Embedded FFmpeg updated to 9.0.2.** This version also fixes, at the source, the MP4 conversions that came out silent (fixed in v1.20.5 by removing the offending subtitle track): the sound now stays complete, and that safety net is kept just in case.
